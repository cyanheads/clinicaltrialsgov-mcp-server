# 2.11.0 — 2026-11-03

## Added

- **Published skill** `clinicaltrialsgov-guide`: served as the resource `skill://clinicaltrialsgov-guide/SKILL.md` (with the `skill://{+path}` template) and shipped in the npm package, Docker image, and `.mcpb` bundle; the server `instructions` point to it.
- **`deferredNctIds`** on `clinicaltrials_search_studies`: the `nctIds` entries the request had no room for, returned unqueried and listed in `content[]`; pass them in a follow-up call with the same criteria (#163).

## Changed

- **`nctIds` on `clinicaltrials_search_studies`** (#163): the request queries the leading IDs that fit beside its other parameters and defers the rest; the list takes at most 1,000 entries and repeats collapse. A list of 564–579 IDs with nothing else set, which 2.10.2 answered whole, now returns its last IDs in `deferredNctIds` (256 bytes are held back so every page of a walk queries the same IDs).
- **`clinicaltrials_find_eligible` `location.state` and `location.country`** are bound to the site's state and country fields instead of matching text anywhere in a site's location (#164). The city stays a search term, a state given with a city also admits sites that file no state, and an accented country also tries its unaccented spelling. Recall (recruiting, age 55): Type 2 Diabetes in Washington state 27 → 21, Mexico 245 → 138, London, England, United Kingdom 27 → 482, Paris, Ile-de-France, France 61 → 587, Prague, Czech Republic 3 → 147.
- **`AREA[LeadSponsor]`** (a structure piece) in `advancedFilter` or a `query*` parameter fails `field_invalid` instead of `query_parse_error` (#170).
- **`clinicaltrials_find_eligible`** declares `field_invalid` and `query_parse_error` for condition entries upstream rejects, so those errors carry a recovery hint.

## Fixed

- **Over-long requests fail as `request_too_long`** on `clinicaltrials_search_studies`, `clinicaltrials_get_study_count`, `clinicaltrials_get_field_values`, and `clinicaltrials_find_eligible`, with the request size and a recovery hint, where 2.10.2 returned an untyped HTTP 414 carrying the upstream error page (#163).
- **`AREA[]` field names** in `advancedFilter` and the `query*` parameters of `clinicaltrials_search_studies` and `clinicaltrials_get_study_count`: a mis-cased name (`AREA[overallstatus]` → `OverallStatus`) or alternate name (`Sponsor` → `LeadSponsorName`, `Collaborator` → `CollaboratorName`) is rewritten to the canonical field and echoed in `searchCriteria`; a name upstream already accepts goes out unchanged. An unknown name or a structure piece fails `field_invalid` with up to three suggestions (#170).
- **`clinicaltrials_find_eligible` site ranking** compares place names folded for case, accents, periods, apostrophes, and ß/æ/ø/ł/ı, so Montréal, Québec, St. Louis, São Paulo, and Wrocław rank the registry-spelled sites at the city tier; the country point and the home-country site filter use the same word test, so a `Korea` request keeps South Korean sites (#166).
- **`clinicaltrials_get_study_results`** flattens line breaks in `content[]` in time linear in the text; output is unchanged (#168).
- **`.mcpb` bundle** starts again: packaging no longer strips the MCP SDK's runtime `skills` modules (#171).
- **Tool descriptions**: `includeIndexedOnly` of `clinicaltrials_get_field_definitions` stated the inverse of its behavior, and `resultsSummary` of `clinicaltrials_get_study_record` pointed at a resource that carries no results.
