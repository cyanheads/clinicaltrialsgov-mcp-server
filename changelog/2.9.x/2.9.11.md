# 2.9.11 — 2026-10-05

## Changed

- **Recovery hints** — the tools and `ClinicalTrialsService` stop forwarding `ctx.recoveryFor`; the framework now fills `data.recovery.hint` from the declaring tool's or resource's `errors[]` contract (mcp-ts-core 0.13.10), so the hint text clients see is unchanged.
- **`analyze_trial_landscape`** — a whitespace-only `topic` now fails as a validation error (`-32007`) with `data.reason: "blank_value"`.
- **`getClinicalTrialsService()`** called before `setup()` throws an `InternalError`.
- **Dockerfile** — production dependencies install in a `deps` stage on `$BUILDPLATFORM` (0.13.10) and musl-only packages are pruned (0.13.11); the image gains a `HEALTHCHECK` and an `org.opencontainers.image.version` label, and no longer sets `MCP_FORCE_CONSOLE_LOGGING`.
- **`.env.example`** documents the opt-ins `LOG_TOOL_FAILURE_PAYLOADS` (0.13.8) and the OTLP traces, metrics, and logs endpoints; the README configuration table adds `LOG_TOOL_FAILURE_PAYLOADS` and the OTLP base and logs endpoints.
- **Packaging** — `"!dist/*.mcpb"` in `files`; `.gitignore` and `.dockerignore` cover every `.env*` file (templates excepted); `.mcpbignore` excludes `logs/`, `.cache/`, and `docs/idea.md`; `bundle` packs through `npx`; the `depcheck`, `prepare`, and `inspector` scripts are gone and `clean` is added.
- Framework skills and `scripts/` (devcheck, lint-mcp, lint-packaging, check-skill-versions, release-github) synced from mcp-ts-core 0.13.12; CodeQL analyzes each language under its own category; CLAUDE.md, AGENTS.md, and the README tool sections updated.

## Fixed

- **`server.json`** — the npm entries drop the `run start:*` package arguments and set `runtimeHint: "npx"`, and the `streamable-http` entry sets `MCP_TRANSPORT_TYPE` to `"value": "http"`, so a registry client launching the HTTP entry starts HTTP (template fix from mcp-ts-core 0.13.11).

## Dependencies

- **mcp-ts-core ^0.13.6 → ^0.13.12** — error `data` no longer carries stack traces (0.13.7) or request context (0.13.8); an argument sent as a JSON-stringified object, or an integer sent for a string, is repaired before validation (0.13.9); MCP SDK 2.1 transport rules (0.13.9); tool error results carry `data.requestId` and close with `request <id>` (0.13.10); `ctx.log` notifications honor `MCP_LOG_LEVEL` (0.13.11); every call logs under a framework-generated `requestId`, the client's JSON-RPC id moving to `jsonRpcId` (0.13.12).
