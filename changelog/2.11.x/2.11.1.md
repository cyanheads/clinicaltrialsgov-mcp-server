# 2.11.1 — 2026-11-03

## Added

- **`locations.nearest.status`** on `clinicaltrials_search_studies`: the nearest site's own recruitment status (the lead site's without `geoFilter`), in `structuredContent` and as `[STATUS]` after the place in `content[]`; absent when the site publishes none. A site that files no place renders as `(unnamed site)` (#173).
- **`adverseEvents.frequencyThreshold`** in `clinicaltrials_get_study_results` summary mode, verbatim as in full mode; absent when the study publishes none (#174).

## Changed

- **`clinicaltrials_find_eligible` site ranking** compares country synonyms (`USA`, `UK`, `Czech Republic`, `Republic of Korea`, `PR`, and others) as the registry's spelling, and US state abbreviations (`WA`, `DC`) as the state name when the country is the United States; the query and `searchCriteria` keep the caller's spelling (#172).
- **`clinicaltrials_find_eligible`** sends its main search, then the condition count, then the location count, so a failed request sends nothing further and the call fails with its error (#176).
- **`AREA[]` names and `sort`** are case-corrected and suggested for index-only pieces (`NumLocations`) and, in `AREA[]` only, search areas (`ConditionSearch`); `sort` never takes a search area. A failed read of either source leaves the call as in 2.11.0 (#179).

## Fixed

- **`searchCriteria` trailers** of `clinicaltrials_find_eligible`, `clinicaltrials_search_studies`, and `clinicaltrials_get_study_count` render each value as a code span (a fenced block when it holds a line break), and find_eligible's no-match notice is escaped and quoted in `content[]`, so each reads back as `structuredContent` carries it (#177).
- **Line breaks in registry text** fold to a space in the single-line `content[]` slots of `clinicaltrials_search_studies`, `clinicaltrials_get_study_record`, and `clinicaltrials_find_eligible`, including non-prose rows of the requested-`fields` dump; `structuredContent` is unchanged (#180).
- **`clinicaltrials_get_study_results`** renders a non-numeric adverse-event threshold (`any`) without a trailing `%` (#174).
- **A 404 or a 400 `incorrect format` from `/studies/metadata`** no longer reads as `study_not_found`: only the single-study route (`/studies/{nctId}`) maps either to it, and a failed `/studies/search-areas` read is logged and skipped, never reported as the call's error (#179).
