# 2.9.3 — 2026-09-02

## Changed

- **`@cyanheads/mcp-ts-core` `^0.12.3` → `^0.12.5`** — an upstream `500`/`501` now classifies as `ServiceUnavailable` instead of `InternalError` (a `500` retries where it previously failed on the first attempt; a `501` is marked non-retryable), a client that disconnects mid-call is reported as a cancellation rather than an internal error, and server identity resolves from the served package instead of the process working directory.

## Fixed

- **A caller that disconnects mid-request no longer gets retried** — `ClinicalTrialsService`'s per-attempt fetch merges the caller's `AbortSignal` with a per-attempt timeout; an abort now raises `RequestCancelled` (-32011) immediately when the caller's own signal fired, while a timeout still retries.
- **`clinicaltrials_get_study_results`'s per-ID fallback rethrows a cancellation** instead of collecting it into `fetchErrors` and walking the remaining IDs one at a time for a caller who already left.
- **`.env.example` documented `MCP_SESSION_MODE=auto`; the `Dockerfile` pins `stateless`** ([#115](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/115)) — `.env.example` now documents `stateless` to match. Doc-only: stdio and modern HTTP clients behave identically under either mode.

## Security

- **SSRF DNS guard now queries both Node resolvers** (inherited from `@cyanheads/mcp-ts-core` `^0.12.5`) — closes a path where a hostname resolvable only through the system resolver (`/etc/hosts`, split DNS, an NSS module) passed the guard and then connected.
