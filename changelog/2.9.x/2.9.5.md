# 2.9.5 — 2026-09-12

## Added

- **`clinicaltrials_search_studies`'s `geoFilter` is validated before the upstream call** ([#123](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/123)) — a unit-less radius, a non-positive radius, and an out-of-range latitude/longitude now fail as a typed `geo_invalid` error instead of reaching ClinicalTrials.gov, which answered those cases with an empty 200 (a bare radius is read as meters), a 500 through the full retry budget, and an unclassifiable 400 respectively.

## Fixed

- **`buildAdvancedFilter` parenthesizes the caller's `advancedFilter` before AND-joining it with the phase constraint** ([#117](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/117)) — Essie has no precedence rule scoping a trailing `OR` back under a preceding `AND`, so a `phaseFilter` paired with an OR-joined `advancedFilter` previously matched phase-less studies too.
- **`clinicaltrials_find_eligible`'s location query is AND-joined with quoted components instead of comma-joined** ([#118](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/118)) — a comma-separated multiword city/state/country reached upstream as loose tokens and could score zero against a study listing exactly that site, so the tool reported no trials in a location that has them. The new shared `quoteQueryTerm` helper (also used for condition terms) strips embedded quotes upstream Essie can't escape.
- **`clinicaltrials_search_studies`'s field-dump fallback no longer drops leaves under a partly-rendered subtree** ([#120](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/120)) — `SEARCH_RENDERED` now names the exact leaves the dedicated renderers emit rather than whole subtrees, so `enrollmentInfo.type`, `leadSponsor.class`, `locations[].zip`, and `locations[].contacts[]` reach `content[]` when requested via `fields`.
- **`clinicaltrials_search_studies` distinguishes an exhausted continuation page from an unmatched search** ([#122](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/122)) — a new `pageExhausted` output field and a matching `format()` line fire only when the call supplied a `pageToken` and got back zero studies, the only signal available to tell finished pagination from a search that matched nothing; the broaden-your-search `notice` is withheld there, since that cohort already matched on earlier pages. A blank or whitespace-only `pageToken` is now rejected through the existing `blank_value` contract (`param: "pageToken"`) instead of restarting the walk at page one or reaching upstream as a malformed cursor.

## Dependencies

- `zod` `^4.5.4` → `^4.6.0`
