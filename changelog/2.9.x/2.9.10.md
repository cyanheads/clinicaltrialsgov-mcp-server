# 2.9.10 — 2026-09-22

## Changed

- **`get_study_results` summary-mode adverse events report per-group counts, not pooled ones** ([#137](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/137)) — `topEvents` rows now carry `byGroup: [{ groupId, numAffected, numAtRisk }]` in place of the pooled `numAffected`/`numAtRisk` pair, keyed against a new `eventGroups: [{ id, title }]` roster on the summary. `format()` prints the roster once under `Event Groups:` and one `groupId: affected/atRisk` cell per group on each event. Event groups can overlap (crossover and second-course arms re-count participants of their parent arm), so a summed figure was never a real participant count. Ranking uses the largest single group's `numAffected` instead of the cross-group sum.
- **`find_eligible`'s fallback recruiting site is chosen by distance, not upstream list order** ([#138](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/138)) — the tool now requests `LocationGeoPoint`. When none of a candidate's matched-tier sites is recruiting, the admitted site is the `RECRUITING` site with the smallest haversine distance to the nearest site of the full matched tier (before the `locationLimit` cap), chosen within the requested country whenever a site there recruits; ties keep match order. It carries `distanceMi`, rendered on its `Locations` entry as "N mi from the nearest matched site". When the matched tier or every candidate lacks coordinates, the first candidate in match order is admitted with no `distanceMi`, and the Sites line says it was picked by match order instead of calling it the nearest. Coordinates are dropped from the returned sites. The tool description and the `locationLimit` and `studies` descriptions state the same rule.

## Fixed

- **`get_study_results` renders a one-group count as "1 group"** — outcome measure lines and the summary-mode adverse-event, participant-flow, and baseline count lines printed "1 groups".
