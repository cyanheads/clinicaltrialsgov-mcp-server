# 2.11.2 — 2026-11-09

## Added

- **`retry_deadline_exceeded` and `upstream_timeout`** error reasons (`Timeout`, retryable) on all seven tools and `clinicaltrials://{nctId}`: the call's time budget ran out, or ClinicalTrials.gov answered HTTP 504 on every attempt (#181).
- **`inputAliases`** on `clinicaltrials_search_studies`, `clinicaltrials_get_study_count`, and `clinicaltrials_find_eligible`: ClinicalTrials.gov REST parameter names (`query.cond` or `query_cond`, `filter.overallStatus`, `filter.geo`, …) and generic names (`condition`, `intervention`, `sponsor`, `phase`, `limit`, `max_results`) reach their canonical inputs; `limit` is `pageSize` on search and `maxResults` on find_eligible. An alias sent beside its target is rejected (#190).
- **`enum_invalid`** declared on `clinicaltrials_find_eligible`, which already raised it for an `AREA[]` enum value in a `conditions` entry such as `AREA[Phase]PHASE9`.

## Changed

- **One 50 s budget per tool call or resource read** covers every request, retry, backoff, and pacer wait, and ends the call with `Timeout` `retry_deadline_exceeded` inside an MCP client's 60 s timeout; a hung upstream previously held a call for four attempts per request. `CT_REQUEST_TIMEOUT_MS` is per attempt (default unchanged), and a budget that runs out after a 429 reports `rate_limited` (#181).
- **`clinicaltrials_get_study_results`** falls back to per-ID fetches only when the batch request failed `ids_not_found`; an outage, rate limit, malformed body, spent budget, or cancellation ends the call instead of returning per-ID `fetchErrors`, and the same three end the per-ID loop (#181).
- **A 504 on every attempt** ends as `Timeout` `upstream_timeout` instead of `ServiceUnavailable`.
- **`field_invalid` for AREA[] and RANGE[] refusals:** a study-level field inside `SEARCH[Location](…)` (#183) and `RANGE[]` on a field that takes no range, `AREA[NCTId]RANGE[…]` included (#187), name the field and the form that works instead of failing as `query_parse_error` with the free-text hint. An `AREA[]` enum rejection names the field's piece for every enum field.
- **`sort_invalid`** suggests only date and numeric fields, and a bare or mis-cased `relevance` goes out as `@relevance` with an auto-correction notice (#184).
- **`fields`** on `clinicaltrials_search_studies` and `clinicaltrials_get_field_values` accepts the full paths `clinicaltrials_get_field_definitions` prints and corrects each to its piece name (#189).
- **`clinicaltrials_get_field_values`** refuses a group or object field (`ConditionMesh`, `LeadSponsor`, `LocationGeoPoint`) as `field_invalid`, naming its leaf pieces, before any request (#191).
- **`clinicaltrials_get_study_record`:** `locationLimit`, `outcomeLimit`, and `referenceLimit` accept `0` to leave that list out, and `content[]` keeps the emptied section's heading, its total, and the limit that left it out (#188). With `nearLocation`, a `locationLimit` states the count shown of the in-range sites, with the total.
- **`clinicaltrials_find_eligible`** no-match notices name only steps that widen the request, each once: a country-only request is no longer told to search with just the country, and an empty condition match gets condition-stage advice. The `geoFilter` step spells the `mi` / `km` radius suffix and `includeUnknownEnrollment=true` (#185).
- **`pageSize` and `maxResults`** no longer advertise a 1000 maximum; a larger value clamps to the per-page cap with a notice.
- **`distanceMi`** rounds to one decimal on `clinicaltrials_search_studies` and `clinicaltrials_get_study_record` sites.
- **Service tests** run on vitest fake timers and no longer wait out the 1 s request pacer (#186).

## Fixed

- **A field or field-value name such as `constructor`** is an unknown-name `field_invalid` instead of a TypeError; the upstream parameter lookup no longer reads prototype keys.
- **A failed field-index load** is tried once per call and retried by the next; a call waiting on another call's load restarts it when the loading call ran out of time or was cancelled and the waiter has time left.
- **A dropped connection on Node** (`cause.code` `ECONNRESET` / `ETIMEDOUT`) is retried as on Bun.
- **A caller's cancellation during field validation** ends as `RequestCancelled` without a false "metadata unavailable" warning.
- **Values a caller sends back** (expressions, field lists) render as code spans in `content[]`.
