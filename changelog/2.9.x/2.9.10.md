# 2.9.10 — 2026-09-22

## Changed

- **`get_study_results` summary-mode adverse events report per-group counts, not pooled ones** ([#137](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/137)) — `topEvents` rows now carry `byGroup: [{ groupId, numAffected, numAtRisk }]` and an `eventGroups: [{ id, title }]` roster, replacing the pooled `numAffected`/`numAtRisk` pair. Event groups can overlap (crossover and second-course arms re-count participants of their parent arm), so a summed figure was never a real participant count. Ranking now uses the largest single group's `numAffected` instead of the cross-group sum; a singular/plural "group(s)" label rides with it.
- **`find_eligible`'s fallback recruiting site is chosen by distance, not upstream list order** ([#138](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/138)) — when none of a candidate's matched-tier sites is recruiting, the admitted site is now the minimum-haversine-distance `RECRUITING` candidate to the matched tier (published `LocationGeoPoint` coordinates), preferring the requested country when one recruits there. The admitted site carries `distanceMi`. Falls back to today's list-order admission, with no `distanceMi`, when coordinates are unavailable.
