# 2.10.1 — 2026-10-23

## Added

- **`find_eligible` `ageUnit`** (#162): `years` (default), `months`, `weeks`, or `days`; `age` is read in that unit, so `age: 7, ageUnit: "months"` reaches a study registered for 6 to 8 months. A non-year unit is echoed in `searchCriteria.ageUnit`.
- **`truncated` / `shown` / `cap`** on `search_studies` and `find_eligible` (#153): set when a request past the per-call cap is served at the cap and more studies match. The `notice` states the numbers and the continuation (`nextPageToken`, or the `searchCriteria` replay).
- **`get_study_results` `deferredNctIds`** (#153): requested IDs past the first 20 distinct, unfetched; `content[]` leads with a `Deferred:` line naming them.

## Changed

- **`search_studies` `pageSize` accepts up to 1000** (#153), the upstream page maximum, and serves a page at the server's per-page cap (`CT_MAX_PAGE_SIZE`, default 200) above it. Only a deployment that set `CT_MAX_PAGE_SIZE` above 1000 sees a lower ceiling.
- **`find_eligible` `maxResults` accepts up to 1000** (#153); each call returns at most 50 candidates.
- **`get_study_results` `nctIds` accepts up to 500 entries, repeats included** (#153); a call fetches the first 20 distinct IDs.
- **Output-only limits lose their maximum** (#153): `get_study_record` `locationLimit` / `outcomeLimit` / `referenceLimit` / `nearLocation.radiusMi`, `get_study_results` `outcomeLimit` / `adverseEventLimit`, `find_eligible` `locationLimit`, and `get_field_definitions` `limit`. A value past the list returns the whole list.
- **`CT_MAX_PAGE_SIZE` bounds only `search_studies` pages** (#153). A value below 50 / 20 no longer clamps the candidates `find_eligible` fetches or the IDs `get_study_results` fetches per call.
- **Count requests send `countTotal=true&pageSize=1&fields=NCTId`** (#160) in `get_study_count` and both `find_eligible` funnel stages; ClinicalTrials.gov answered `pageSize=0` with ten full studies. Outputs are unchanged.
- **`get_field_values` `longest.value` is capped at 2,000 characters** (#161): longer values carry `longest.truncated: true`, `length` keeps the full length, and a `notice` names the `search_studies` call (`nctIds` + `fields`) that returns the whole text.
- **`get_field_values` `content[]` keeps Markdown in values inert** (#161): `topValues` entries are backslash-escaped, and a `longest` or `topValues` value with line breaks renders as a fenced block. `structuredContent` keeps values verbatim.

## Fixed

- **An invalid `CT_*` value fails at startup with the configuration banner** (#157), on stdio and HTTP, instead of an uncaught stack at tool import. `CT_MAX_PAGE_SIZE` must be an integer ≥ 1 (above 1000 clamps to 1000) and `CT_REQUEST_TIMEOUT_MS` a positive integer; `0`, `-1`, and `1.5` now fail startup.
- **`find_eligible` matches every location part at one site** (#159): `searchCriteria.location` is `SEARCH[Location](…)`, with each part quoted unless it is a single run of letters and digits. City and state credit goes only to sites whose country contains every word of the requested one, so London, UK no longer leads a London, Canada match.
- **`get_field_values` no longer renders uncounted free-text fields as `0 unique values`** (#165). The header reads `distinct values not counted` and `structuredContent` carries `uniqueValuesCounted: false` beside the upstream's `uniqueValuesCount: 0`.
