# 2.11.3 — 2026-11-13

## Added

- **`upstream_unavailable` and `upstream_rejected`** error reasons (`ServiceUnavailable`) on all seven tools and `clinicaltrials://{nctId}`, each with a recovery hint: `upstream_unavailable` is retryable, `upstream_rejected` is not ([#196](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/196)).

## Changed

- **The field dump** computes its labels incrementally, spending less CPU on them.

## Fixed

- **A malformed 200 body** (text that is not JSON, an HTML page under any content type, `null`, or the wrong top-level shape for its route) is retried, then ends `upstream_unavailable` naming the route, instead of answering as a success, a `ValidationError` quoting the parser, or an internal error. A count body without a numeric `totalCount` is an outage, never `0` ([#196](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/196)).
- **A 500, 502, or 503, or a dropped connection, on every attempt** ends `upstream_unavailable` with `data.lastError` a fixed value or the transport code, never upstream or runtime text ([#196](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/196)).
- **A 408** is retried, and a 408, a 504, or an attempt that ran out `CT_REQUEST_TIMEOUT_MS` on every attempt ends as `upstream_timeout` ([#196](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/196)).
- **Statuses the service does not translate** are sent once: 501, any 3xx, and any 4xx other than 400, 404, 408, 414, and 429 end `upstream_rejected`; any other 5xx ends `upstream_unavailable`. An HTML page in place of the API's own 404 ends `upstream_rejected`. The message names the status, and the body stays server-side ([#196](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/196)).
- **A refused connection or an unresolvable host name** (`ECONNREFUSED`, `ENOTFOUND`) is sent once and ends `upstream_unavailable` with the code in `data.lastError`; 2.11.2 rethrew it with no reason.
- **An empty `/studies/metadata` answer** is a failed read and is never cached; the next call reads again instead of refusing every `fields` name until restart ([#196](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/196)).
- **A hung `/studies/metadata` read** no longer costs a call its 50 s budget: field validation reads it once under 5 s and sends the request unvalidated on failure ([#192](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/192)). `clinicaltrials_get_field_definitions` search keeps the full retry ladder, and the results batch and `clinicaltrials_find_eligible` send no metadata read.
- **`clinicaltrials_get_field_values`** names in a `notice` the fields whose `multiValued` it could not settle, which carry no flag ([#192](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/192)).
- **`clinicaltrials_get_field_values`** accepts index-only pieces (`NumLocations`, `StudyFirstPostYear`) and record alt names (`OVERALL-STATUS`), folds case (`numlocations` → `NumLocations`), refuses search areas such as `ConditionSearch`, and flags an index-only piece under a repeated node as `multiValued` (`LocationCountryCode`) ([#194](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/194)).
- **An exact record alt name that folds to a group** (`COLLABORATOR`) goes out as written and is answered (`CollaboratorName`); 2.11.2 refused it.
- **An index-only read that lists no index-only piece** is a failed read and is never kept; the next call that needs the index-only pieces reads again.
- **`clinicaltrials_search_studies`** caps a page at 10 studies, or the server's `CT_MAX_PAGE_SIZE` when lower, when `fields` names `ResultsSection`, a module or group under it, or a list the field metadata cannot check; `truncated`, `shown`, `cap`, the notice, and `nextPageToken` disclose it ([#198](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/198)).
- **`clinicaltrials_get_field_definitions`** overview and search `content[]` state `totalFields`, which only `structuredContent` carried.
