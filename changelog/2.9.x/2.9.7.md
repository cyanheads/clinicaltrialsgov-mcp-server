# 2.9.7 — 2026-09-13

## Changed

- **Blank or unsubstituted `${...}` config values read as unset, so defaults apply** (mcp-ts-core 0.13.0, [#427](https://github.com/cyanheads/mcp-ts-core/issues/427)) — an empty `CT_REQUEST_TIMEOUT_MS` previously coerced to `0` and an empty `CT_API_BASE_URL` was taken as-is.
- **`manifest.json` wires its MCPB `user_config` options into `mcp_config.env`** — `CT_API_BASE_URL`, `CT_REQUEST_TIMEOUT_MS`, `CT_MAX_PAGE_SIZE`, and `MCP_LOG_LEVEL` were declared but never passed to the server, so a value set in the install UI had no effect. An option left blank takes its default.
- **Development skills moved from `skills/` to `framework-skills/`** (mcp-ts-core 0.13.0, [#428](https://github.com/cyanheads/mcp-ts-core/issues/428)) — installing this server's Claude Code or Codex plugin no longer loads its development skills into the installing agent.
- **`bun run audit:fix` runs `bun audit fix`** (mcp-ts-core 0.13.0, [#363](https://github.com/cyanheads/mcp-ts-core/issues/363)) — `bun audit` has no `--fix` flag, so the script audited and changed nothing.
- Framework tooling synced from mcp-ts-core: `lint:packaging` checks MCPB `user_config` wiring (0.13.0), `devcheck` parses Bun 1.4 `bun audit` output (0.12.9), and the `devcheck` outdated gate no longer holds `@cyanheads/mcp-ts-core`.
- Docs and packaging metadata synced: issue forms allow blank issues and link the private security advisory form, contributor docs no longer invite pull requests, `.claude-plugin/plugin.json` gains author contact and `keywords`, and `.env.example` documents `MCP_HTTP_MAX_BODY_BYTES` and `MCP_GC_PRESSURE_INTERVAL_MS` and drops the unused `CT_MAX_ELIGIBLE_CANDIDATES`.

## Fixed

- **The HTTP landing page's curl snippet now completes `initialize`** (mcp-ts-core 0.12.9, [#395](https://github.com/cyanheads/mcp-ts-core/issues/395)).
