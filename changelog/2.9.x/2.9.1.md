# 2.9.1 — 2026-08-18

## Changed

- **`nearestPieces` no longer returns three did-you-mean suggestions for a field or sort name related to nothing.** The keyword path now requires a minimum score of 100 and the Levenshtein fallback a distance within half the longer string's length; an input clearing neither floor returns an empty list, and both callers already render that case without a blame clause. ([#112](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/112))
- **The `blank_value` recovery hint and `blankValueMessage` now lead with supplying a non-blank value or list entry**, offering omission only as a trailing option for parameters that are actually optional — omitting a required parameter fails the schema with a bare `-32602` and no recovery hint. ([#113](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/113))

## Removed

- **Dropped `test:conformance`, `build:worker`, `deploy:dev`, and `deploy:prod`** — all four pointed at a Worker entrypoint, `wrangler.toml`, and a conformance config deleted in the mcp-ts-core framework migration. The `@cloudflare/workers-types` devDependency and its `devcheck.config.json` entries go with them. ([#111](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/111))

## Added

- **`tests/mcp-server/tools/tool-contract.test.ts`** wires `toolContractSuite` against all 7 tools — success and error cases validated against declared output schemas and the wire error envelope (`isError`, `structuredContent.error.code`, `.data.reason`, the `Recovery:` line), coverage the per-tool handler tests didn't reach. ([#111](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/111))
