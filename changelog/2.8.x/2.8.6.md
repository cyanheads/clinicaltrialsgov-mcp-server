# 2.8.6 — 2026-08-18

## Fixed

- **`clinicaltrials_search_studies` `format()` no longer cross-contaminates repeated array leaves** — a leaf's dedup key now carries the fully-qualified path of the array entry it belongs to, so entries that share a humanized label (e.g. multiple `secondaryIdInfos`) no longer collapse into one line splicing fields from different entries; a repeated array's label also carries its entry index (`Secondary Id Infos[1] > Id`) for `content[]`-only readers. ([#86](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/86))
- **`clinicaltrials_search_studies` no longer emits a `nextPageToken` after the first page already exhausted the results** — dropped only when provably exhausted: a fresh search (no incoming `pageToken`) whose `totalCount` this page already covers. A continuation page's opaque upstream cursor is passed through unchanged, since there's no consumed count to compare it against. ([#98](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/98))
- **Blank, whitespace-only, and empty-list inputs are now rejected with a new `blank_value` reason** — `clinicaltrials_search_studies`, `clinicaltrials_get_study_count`, `clinicaltrials_get_study_results` (`sections`), `clinicaltrials_find_eligible`, and the `analyze_trial_landscape` prompt's `topic` argument previously treated a supplied-but-blank value as an omitted one, silently widening or dropping the constraint instead of rejecting it; `sections: []` returned a study stripped of every results module with no signal anything was omitted. Omission still means "no filter" — only a value the caller actually supplied is judged. ([#99](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/99))
- **`clinicaltrials_get_study_results` no longer declares an unreachable `study_not_found` error contract** — the handler never threw it; failed IDs land in `fetchErrors` instead. Removed. ([#101](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/101))
- **`clinicaltrials_get_study_results` re-throws a rate-limit failure instead of swallowing it into `fetchErrors`** — a 429 from the batch endpoint previously fell into the per-ID fallback and fired up to 20 more sequential requests at the already-rate-limited upstream. Now surfaces the typed, retryable `rate_limited` error immediately and issues nothing further. ([#103](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/103))

## Changed

- **`tsconfig.json` now typechecks `src/` and `tests/` together** — `tsconfig.build.json` carries the emit config (`rootDir: src`, `outDir: dist`), `tsconfig.test.json` is deleted, and `typecheck` runs a single `tsc --noEmit`. Closes a real gap: tests were never typechecked, and 206 errors had accumulated silently in them.
- **`lint:mcp` script added to `package.json`** — the definition linter shipped without a script entry.
- **`Dockerfile` production installs pass `--omit=peer`** — drops the framework's optional peer tiers (test runner, service SDKs, parsers) Bun would otherwise auto-install; the conditional OTel install carries the same flag so it doesn't re-resolve them back in.
- **`.github/SECURITY.md`** contact address updated to `security@caseyjhand.com`.
