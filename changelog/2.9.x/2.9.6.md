# 2.9.6 — 2026-09-12

## Added

- **`get_study_record` documents now carry a `downloadUrl`** — each `largeDocs[]` entry gets a CDN link built from the study's own NCT ID and filename, since the upstream `LargeDoc` schema carries no URL of any kind. Applied to both the tool and the `clinicaltrials://{nctId}` resource. Observed CDN pattern, not a documented API contract. [#125](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/125)

## Changed

- The `devcheck` outdated gate allowlists `@cyanheads/mcp-ts-core`, so a newer framework release no longer fails the gate. The dependency stays at `^0.12.8` here; adopting a newer one is its own release.

## Fixed

- **`get_field_values` no longer drops INTEGER/NUMBER/DATE/STRING statistics** — `min`/`max`/`avg`, date `formats`, and STRING's `longest` value are now declared on the output schema and rendered in `format()`; previously only the ENUM/STRING value buckets and the BOOLEAN counts survived. [#119](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/119)
- **`multiValued` now covers a scalar leaf under a repeated ancestor** (e.g. `LocationCountry` under `Location[]`), not just an array-typed leaf itself — a new `hasArrayAncestor` flag threads repeated-object state down the field-metadata walk. [#121](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/121)
- **`get_field_definitions` rejects arguments that don't belong to the selected mode** — a cross-mode argument (`mode_mismatch`), a blank required value (`blank_value`), or an omitted one (`mode_requires`) now returns a typed, declared error with a recovery hint. Previously a cross-mode argument was dropped silently, a whitespace-only one reached the field tree and came back described as an empty or unknown part of the tree, and an omitted one threw a plain `validationError` outside the tool's error contract. [#49](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/49), [#132](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/132)
- **`search_studies` names unmatched `nctIds` in its empty-result notice** — an ID-only search that matched nothing now points at `get_study_record` and `get_study_results`; an ID combined with other criteria gets an added clause alongside the existing broadening guidance. [#130](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/130)
