# 2.8.3 — 2026-07-26

## Changed

- **`.mcpbignore`-unreachable bundle content** — `scripts/clean-mcpb.ts` and `scripts/lint-packaging.ts` now also strip/verify platform-specific `@duckdb/node-bindings-*` native bindings, alongside the existing dependency-shipped agent-doc strip, so a packed `.mcpb` stays portable across platforms.
- **`scripts/devcheck.ts` outdated-package gate** — peerDependency rows (which declare a floor, not a target) are excluded from the check, and the `minimumReleaseAge`-hold detection is simplified to a plain `Update === Current` comparison.
- **`scripts/check-dependency-specifiers.ts`** now also scans the `overrides` section for floating specifiers (`latest`, `*`, dist-tags), since an override exists to pin a transitive off a known-vulnerable version and a floating specifier there would silently re-resolve past the pin.
- **`LICENSE`** copyright line → `Casey Hand @cyanheads`. **`.github/FUNDING.yml`** added.

## Fixed

- **`ClinicalTrialsService.throttle()` no longer collapses concurrent callers onto one instant** — each caller now claims its slot by chaining onto an instance-held promise queue instead of all reading the same `lastRequestAt` and sleeping in parallel. Measured: three concurrent requests went from gaps of `[0, 0]`ms to `[1002, 1002]`ms; `clinicaltrials_find_eligible`'s three-call `Promise.all` now genuinely costs ~2.2s (previously ~1.2s), and its code comment is corrected to say so. ([#92](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/92))
- **`clinicaltrials_search_studies` malformed `geoFilter`/`sort` classification** — a malformed `geoFilter` now throws a `geo_invalid` error naming the required `distance(lat,lon,radius)` shape and the `mi`/`km`-suffix requirement, instead of passing the raw upstream body through with no reason or recovery hint; `sort_invalid` gains a recovery hint it previously lacked. The classifier reads the offending parameter name out of the upstream body (`` Parameter `filter.geo` has incorrect format ``) rather than inferring it from which params were sent, so a request with both a bad `geoFilter` and a valid `sort` is no longer misattributed to `sort`. ([#93](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/93))
- **Essie query-parse error messages** — `describeQueryParseError` now names the actual offending token for each upstream shape (`mismatched input`, `extraneous input`, `no viable alternative`, `token recognition error`, `missing 'Y' at 'X'`) instead of reporting the token the parser expected; handles the previously-unmatched `extraneous input 'X'` shape; and corrects the bracket-reservation claim — `AREA[Field]value`/`RANGE[min,max]` expressions work in the free-text params (`query`, `conditionQuery`, `advancedFilter`, `phaseFilter` all return identical counts for the same expression) and only a *stray* bracket fails. Fourteen `.describe()` strings plus the `query_parse_error` recovery hint are corrected to match. ([#94](https://github.com/cyanheads/clinicaltrialsgov-mcp-server/issues/94))
